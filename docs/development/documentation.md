# 文档站使用

文档站由 VitePress 渲染仓库中的 Markdown，独立于 DogX 的 API、RPC 和管理前端，不需要数据库。仓库中的文档是唯一维护来源，浏览器页面是阅读界面，不另行维护一份重复正文。

## 环境与启动

与 `dogx-web` 使用同一套工具版本：Node.js **22.22.1**、pnpm **11.16.0**。`docs/.node-version` 固定开发版本，`docs/package.json` 的 Node 支持范围与管理前端一致；后续升级时一起调整。

在 `dogx` 仓库根目录执行：

```powershell
pnpm --dir docs install --frozen-lockfile
pnpm --dir docs dev
```

启动后访问 <http://127.0.0.1:5173/>。修改 Markdown 或站点配置后，开发预览会自动更新。端口被占用时启动会明确报错，不自动换到另一个地址。

默认只监听本机回环地址，不发布到公网。多人访问、正式部署和访问控制需要另行配置；不要把开发服务器直接暴露到公网。

## 阅读方式

- 左侧文档导航按软件设计说明书章节、项目规划、开发规范和 ADR 分组。
- 右侧本页目录跳转到当前文档的小节；窄屏使用页面上的目录入口。
- 顶部搜索在本站文档中查找内容，不使用外部搜索服务。
- Mermaid 代码块在浏览器中渲染为图表，不需要读者查看图表源码。

文档中的“已确认”表示设计决定已经通过，不代表对应功能已经开发完成。设计进度以各篇正文中的状态为准。

定时任务设计从[软件设计说明书总览](../design/scheduler/index.md)进入。总览介绍目标和架构并给出章节地图；各章维护对应主题，设计进度与评审计划单独维护当前议题和阶段完成标准。旧 `roadmap/job.md` 保留入口指引，不再维护重复正文。

## 维护约定

站点配置位于 `docs/.vitepress/config.mts`。新增页面后，将其加入左侧导航；使用相对 Markdown 链接或站内路径关联其他文档。现有文件路径保持不变，GitHub 中的文档链接仍可使用。

VitePress、Mermaid 与社区插件 `vitepress-plugin-mermaid` 的直接依赖固定版本，间接依赖由 `pnpm-lock.yaml` 锁定。三者均采用 MIT 协议。Mermaid 使用严格安全模式，不启用宽松 HTML 或图内脚本点击能力；图表仍需要在浏览器中检查实际渲染结果。

插件从项目根解析部分间接依赖，因此 `pnpm-workspace.yaml` 的依赖提升只作用于文档工程，不修改 `dogx-web` 的依赖配置。依赖安装仅允许 `esbuild` 执行构建脚本。

`node_modules`、VitePress 缓存和生成的站点文件不提交。文档变更与代码一样通过 Git 查看差异；更新设计结论时保留已确认与待讨论的边界。

## 静态发布

需要交付静态站点时执行：

```powershell
pnpm --dir docs build
```

生成目录为 `docs/.vitepress/dist`，构建命令不会自动上传或发布。日常阅读使用上述本机开发预览；部署到 Nginx 等静态托管环境时，需要单独配置访问范围与鉴权。
