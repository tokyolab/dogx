# DogX v0.1 功能边界

v0.1 的目标是得到一套可复用、可测试、可独立部署的后台管理骨架。

## 阶段 1：基础骨架

- go-zero `system-api` REST/BFF 进程
- go-zero `system-rpc` gRPC 进程
- API → RPC 的 zrpc 调用链
- 示例配置与密钥隔离
- RPC 中的 PostgreSQL / GORM 初始化
- RPC 中的 Redis 初始化
- Goose SQL 迁移命令
- 用户、角色、菜单和关联表的初始模型
- `/health` 与 `/ready`
- 单元测试和基础 CI

## 阶段 2：认证闭环

- 账号密码登录、刷新令牌、退出
- 当前用户信息
- 会话管理与登录日志
- 密码安全策略

## 阶段 3：单租户 RBAC

- 用户、角色、多应用菜单、页面元素与接口资源
- 菜单和接口分别授权，SQL 保存管理数据及关联关系
- Casbin 中间件判定接口权限
- 权限策略变更后的同步和失效机制

## 阶段 4：Vben5 联调

- 独立 `dogx-web` 仓库
- 登录、动态菜单、页面元素权限和接口授权
- 用户、角色、菜单基础页面
- 统一错误处理和请求追踪 ID

## 不在 v0.1 中

- 多租户
- 移动端功能
- 没有清晰边界的额外服务拆分
- 普通 CRUD 的自动 Redis 缓存
