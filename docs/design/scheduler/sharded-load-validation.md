## 查询与组件验证

- 统一到期 Task 查询：使用真实 GORM 生成的语句和原参数执行 `EXPLAIN (ANALYZE, BUFFERS)`，覆盖初页、续页、终态历史量，以及大量父已停止／到期的过滤。保留优化器选择，不关闭顺序扫描来强迫使用索引；分别记录实际返回数、扫描与过滤、Buffer 和耗时，`LIMIT` 不代表最多只扫描这么多行。
- 检查与生成：通过完整 Checker 在原共享 2 秒预算内生成 500 片，包含接近报文上限的准备输出，记录真实事务和查询耗时、SQL 数量及连接池等待；不只测批量 INSERT 后声称整个检查达标。
- 检查队列混合：保留默认合并窗口和工作并发，混合普通完成、分片生成与阶段检查；记录提示到处理的延迟及处理耗时，验证有限接纳工作均能推进，无预算超时或重复生成。百分位只作为该组件场景实测，不扩展为生产保证。

## 环境与测量边界

本轮在 Windows 11、Intel Core i5-13500H（16 个逻辑处理器）、约 31.8 GiB 内存的开发工作站执行。使用 Go 1.27.0、PostgreSQL 18.6、Redis 7.4.2 和 etcd 3.5.21；每个 Go 进程 `GOMAXPROCS=2`，构建／测试 `-p 2`，同一 checkout 不并行运行测试。依赖全部使用独立回环端口、测试数据库及隔离 Schema，不连接开发业务库或读取私密配置。

真实 Cron 产生正常负载波次，管理 RPC 只负责准备和启停规则；不会以串行手动触发替代同秒到期。只在停止专项调用公开停止入口。测试宿主沿用生产 `run`，只注入测试处理器和资源采样，不修改生产入口、依赖或日志级别。

业务开始时间取业务记录中的数据库时间，Task 的尝试登记时间不能代替业务实际开始。数据库字段在提交前赋值，其差值不称为精确 COMMIT 延迟；全部完成另以独立查询可见时刻计算。500ms 采样可能漏掉短尖峰或 NOWAIT 快速失败，零等待样本不代表没有竞争。ACK 绑定可能晚于结果，允许成功 Task 双绑定都为空，拒绝半绑定；BUSY 可增加执行编号但不得扣除业务机会或造成重复业务。

本轮新增负载用例采用 `integration,e2e,load` 标签，独立于日常 CI；进程 E2E 不采集子进程覆盖率，本机性能值不代替该提交的 Linux、race 或 CI 覆盖率。
