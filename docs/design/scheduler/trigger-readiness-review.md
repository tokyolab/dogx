## 本批的完整输入与输出 {#batch-boundary}

输入包括管理请求、Cron 回调、注册后到期检查、Leader 接任检查和每分钟触发恢复。自动来源都只提交 Job ID 提示，统一事务读取当前 Job 决定创建还是跳过。

成功创建的输出是数据库中一条 WAITING Instance，包含组身份、触发身份和完整 `execution_config`。自动创建与 `next_trigger_at` 推进同事务提交；手动创建与请求号防重同事务完成。开始、截止、结束时间为空，后续执行模块才设置首次开始并启动整轮倒计时。

| 能力 | 本批处理方式 | 验收时怎样观察 |
| --- | --- | --- |
| Job 创建、编辑、启停、删除 | 八条管理接口中的对应动作，保留既有并发和引用保护 | HTTP／RPC 契约测试与数据库事实 |
| 预览、列表、详情 | 同一服务端 Cron 计算，轻量列表，两次查询，无 N+1 | 协议测试、Repository 集成测试 |
| 手动执行 | 返回已创建的 Instance ID；同请求号重发查重，不宣称业务完成 | 请求重复、参数冲突、与自动创建竞争的测试 |
| 规则运行 | etcd 选主，robfig 长期规则，独立配置同步和遗漏恢复 | 两个以上调度副本与真实依赖测试 |
| 执行器组依赖 | 正式五字段组表、真实行锁和引用校验，测试数据由夹具准备 | 不存在／已删除组拒绝；无在线节点仍可引用 |
| 后续交接 | 仅以已提交 Instance 和快照交接；本地 ID 提示不是可靠消息或执行权 | 提交后退出仍可查到，当前 Job 编辑不改旧快照 |

本批尚无完整组管理入口，也没有业务推进消费者，因此不作为面向最终用户的可运行调度功能发布。待开始 Instance 持续参与阻塞判断；测试通过受控的前轮终态数据覆盖后续触发，不增加临时过期或自动结束逻辑。页面和 Task 模块后续补齐，不因此削减第一版范围。

## 持久化与事务总表 {#persistence-review}

| 对象或操作 | 落地要求 | 设计依据 |
| --- | --- | --- |
| `job_executor_group` | 五字段正式组依赖，含 `deleted_at`，无启停状态列 | [组生命周期](data-contracts.md#executor-group-lifecycle) |
| `job_definition` | 完整 Job 配置、触发进度和删除时间；应用明确填入缺省值 | [Job 字段](data-contracts.md#job-field-draft) |
| `job_instance` | 自动／手动身份、固定配置、状态和可空运行时间；无整轮 owner | [Instance 字段](data-contracts.md#instance-field-draft) |
| 自动触发 | Job 主键单行锁，锁后取调度进程时间，后续独立语句检查活跃轮次；创建／跳过和进度原子提交 | [触发事务](data-contracts.md#trigger-transaction-proposal) |
| 手动创建 | 同 Job 协调，先查同 UUID 原记录，再判新建条件；不能把响应不明当作未创建 | [手动记账](execution.md#manual-trigger-accounting) |
| 新建／完整编辑 | 目标组行锁协调引用，组→Job 锁序；只锁新目标组，配置编辑不能写启停或进度 | [组引用并发](data-contracts.md#group-reference-concurrency-proposal) |
| Job 删除 | 已停用且无待开始／运行中 Instance 才设置删除标记；不清理历史或取消 Task | [删除协议](data-contracts.md#job-deletion-proposal) |
| 索引 | 五条触发访问路径，加一条按执行器组查询 Job 的管理索引；无额外名称模糊搜索索引 | [SQL 对照稿](trigger-sql-review.md) |

继续使用 READ COMMITTED、单表主键单行短锁、无物理外键及业务数值范围 CHECK。事务内不调用 etcd、Redis 或 RPC。仅指定的自动／手动身份冲突执行 `DO NOTHING`；手动仍需读取原记录比较内容，其他约束或技术失败不得吞掉。组删除的完整接口暂不开放，不能在缺少 Task 收敛和凭据失效协议时借五字段表伪装完成。

WAITING Instance 的 ID 分页只辅助有界查询，不能成为永久消费水位；较小 ID 可以晚提交。后续执行模块沿用持久化状态重新覆盖遗漏，不从当前 Job 重建快照，也不为本批新增另一套轮询消费者。

## 运行参数与资源归属 {#runtime-review}

以下均沿用已通过的初值，不增加新的 Job 页面选项。配置字段拼写及结构体在编码时映射这些含义，不改变值和作用范围。

| 项目 | 初值或规则 | 不能误解为 |
| --- | --- | --- |
| 待处理 Job 总容量 | 1024，排队与处理中的不同 Job 合计 | 启用规则数量上限 |
| Instance 创建并发 | 每进程 32，自动与手动共用 | 全集群额度或执行器并发 |
| 单次触发处理 | 3 秒，含取得创建额度、数据库连接、锁等待和提交 | 自动排队时间上限或业务执行超时 |
| Leader 恢复读取 | 每分钟一批，LIMIT 1024，查询预算 5 秒 | 遍历全表、跨周期游标或一分钟恢复承诺 |
| 配置核对 | 每分钟全量轻量读取启用规则，查询预算 5 秒 | 仅加载前 1024 条或与恢复共用一个循环 |
| Leader 租约 | 15 秒 | 固定接任 SLA 或数据库提交隔离 |
| 通知与 Watch | 提交后通知最多 1 秒；重建按 1 至 30 秒带抖动退避 | 已落库保存必须等所有副本应用成功 |
| 固定错失容忍 | 5 秒，由锁后调度进程时间判定 | Instance 或 Task 执行超时 |

`robfig/cron/v3` 拟锁定 v3.0.1；etcd client/v3 沿用当前依赖 v3.5.21，不顺带升级 go-zero。Cron 库的旧 Go 最低版本声明不是最高版本限制；与项目当前 Go 工具链的兼容性由实现时的真实编译和测试验证。

配置快照和 Cron 条目内存随启用规则数增长，不把有界触发队列宣传为整个进程内存恒定。首次完整装载与热更新都按已定批次确认初始化，不能仅以 `Start()` 返回证明已就绪。本机旧任期未清理完不重新参选；自动工作使用任期上下文，手动额度和进程连接跨任期保留。

## 本次已通过的接入细则 {#integration-decisions}

这些代码映射与工程衔接已随本次总审批准，不改变此前已定的总体架构。

1. **进程归属。** 新增 `apps/job/rpc`，管理 RPC 和 Leader 运行组件在同一调度进程；`system-api` 增加 Job 客户端，不新增 `job-api`。Job RPC 暂不可达不阻断原系统启动，也不扩大原 `/ready` 的故障范围。
2. **迁移与权限。** Job 域独立 Goose Provider 和 `job_goose_db_version` 账本；System 保留原迁移流并登记八条 `sys_api` 记录。不开启各副本自动迁移，不产生隐含默认组。
3. **规范例外。** 以 ADR-0009 限定 etcd 选主／发现／通知用途，并同步 AGENTS、生成与迁移规范；不推广为业务锁全面迁移。
4. **接口落地。** 附件给出具体字段、存在性、RPC 编号和稳定 subcode 候选；保留既有 trim、空值、手动覆盖和重试规则，不借契约生成改变产品语义。
5. **CI 范围。** 保留全量单元测试，增加 Job 数据库路径、etcd 测试依赖和多副本故障场景，不能让写好的集成测试因路径枚举遗漏而不运行。

当前仓库代码、规范和 CI 尚未应用这些修改；待用户明确要求开始实现后，作为本批实现的一部分交付。

## 测试到交付的对应关系 {#acceptance-matrix}

下表是实施与评审清单，不是已经通过的测试报告。普通单元测试使用窄接口 Stub；SQL、约束和行锁使用真实 PostgreSQL，选主／Watch 使用真实 etcd。

| 编号 | 必测场景 | 测试层与通过标准 |
| --- | --- | --- |
| T01 | 六字段 Cron、时区、无下次时间、精确 5 秒及略超边界、多轮遗漏 | 单元；与[触发判定](behavior.md#trigger-identity)和[错失规则](behavior.md#misfire)一致，所有 Next 入口共用解析规则 |
| T02 | 字段省略／null／空串／0／false、trim 后 Unicode 长度、手动先验组合再 trim | HTTP／RPC；不丢存在性，不静默截断，不把原参数改写为 JSON |
| T03 | 三表迁移、注释、索引、身份结构与约束冲突 | PostgreSQL；Up／Down、同库独立迁移账本、自动与手动唯一性均符合契约 |
| T04 | Cron／恢复／手动竞争，首次启用与编辑／启停／删除竞争 | PostgreSQL 多连接；不双建同一身份、不产生半套进度快照、不错误跨过阻塞 |
| T05 | 新建／改组与组删除标记竞争，已删组、无在线节点 | PostgreSQL；验证共同组行锁和新引用过滤，完整运行期删组仍留后续模块 |
| T06 | 重复手动 UUID、规范化参数冲突、响应丢失、已删除 Job | 协议＋PostgreSQL；按原号核对，不把旧实例重开，不把不明提交说成回滚 |
| T07 | 提示去重、处理中再到达、队满、共享 32 额度、处理取消 | 单元＋race；不丢处理中新提示、不超额、不提前归还尚在执行的操作额度 |
| T08 | 首次加载失败、合法空配置、无效单条、热更新、注册后到期检查 | 适配器＋依赖集成；失败不应用半批，未变化规则不重建，不漏重载中的新核对信号 |
| T09 | 多副本选主、失主时加载／事务在途、重复切主、清理受阻 | etcd＋PostgreSQL；单节点不叠加任期，允许旧合法提交但不重复创建同一自动身份，不虚构固定接任时限 |
| T10 | 通知丢失、Watch 中断／压缩、数据库故障、恢复队满 | 依赖集成；按分钟兜底且不自循环空转，保持已定头部候选可能阻塞的边界 |
| T11 | 提交后通知前退出、旧快照重读、较小 ID 晚提交 | PostgreSQL／交接；工作仍可按状态发现，开始／截止保持空，不以 ID 永久水位漏掉记录 |
| T12 | 八条管理路由、权限拒绝、RPC 不可达、技术错误脱敏、列表固定查询数 | 路由安全矩阵＋协议；未登录／未授权拒绝，Job 故障不拖垮原 System 功能，无 N+1 |

本批性能检查使用 500 条启用规则、100 条同秒到期，另验证超过 1024 条规则不会被配置加载截断；关注延迟、队列拒收、数据库锁等待及内存／协程是否持续增长。分片吞吐与执行器回报性能不在本批测量范围。不宣称达到 SnailJob 指标，也不在测完之后倒定性能验收阈值；量化性能目标仍在明确资源后、正式压测前评审。

### CI 和本地验证范围

- 已有 `go test ./...` 会覆盖新增 Job 普通单元测试；Linux 继续 race 与随机顺序，Windows 继续普通测试。
- 现有集成命令只枚举 System 路径，实施时须明确加入 Job Repository、迁移和 RPC 装配测试，并保留原测试。
- 增加受测试控制的 etcd 依赖与多副本场景；不访问公网或共享开发环境，不用固定长睡眠代替完成条件。
- API 仍通过 `system.api` 验证和生成；Job RPC 按其独立 Proto 生成，检查生成物无手改。
- 长时间及故障测试记录实际退出资源、协程数量、数据库连接和队列容量；文档渲染、链接检查不计入上述功能测试。
