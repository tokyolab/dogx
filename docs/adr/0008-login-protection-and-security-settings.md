# ADR-0008：登录限流、失败锁定与安全设置

- 状态：已实施，待 CI 集成验证
- 日期：2026-09-30
- 关联：[ADR-0003](0003-authentication-and-session.md)、[ADR-0004](0004-single-tenant-rbac.md)

## 背景

DogX 已有登录认证和登录日志，但需要限制频繁登录请求与持续猜测密码，避免无约束的密码计算、数据库查询和日志写入。第一版只实现登录专项保护，不建设通用限流管理平台。验证码近期计划接入，因此请求限流采用可复用中间件；本次不提前实现验证码功能。

## 决策

### 范围与页面

- 入口为“系统管理 → 安全设置”，使用顶部线条式页签，分类导航与表单放在同一张卡片内。
- 第一版只有“登录保护”页签，包含“请求限流”和“失败锁定”两个分区，不再嵌套页签。
- 开关和参数均在点击“保存”后生效。一次保存提交登录保护整组设置；前端不因未修改而跳过请求。
- 不展示接口安全、验证码等未实现分类或占位页面，不预留对应数据库字段和接口。
- 不做通用接口限流规则表、接口选择、算法选择、短信限流、安全预警或手动解锁页面，不新增业务定时任务模块。
- 现有密码规则、Token 有效期和会话撤销规则保持不变，JWT 签名密钥等部署配置不搬入本表。

### 权限

- 沿用现有菜单与 API 独立授权体系：菜单权限控制页面入口，服务端通过对应 API 权限校验查询、修改操作，不依赖前端是否展示页面。
- 不新增“仅超管可修改”的硬编码限制。普通用户具有对应 API 权限时也可操作；超管沿用现有鉴权规则。
- 登录限流和失败锁定对超管同样生效，不因超管身份绕过登录保护。

### 初始参数

| 配置 | 默认值 |
| --- | --- |
| 请求限流 | 开启 |
| 请求统计时长 | 60 秒 |
| 窗口内最大请求次数 | 30 次 |
| 失败锁定 | 开启 |
| 失败统计时长 | 15 分钟 |
| 失败次数阈值 | 5 次 |
| 锁定时长 | 15 分钟 |

- 页面说明限流按同一 IP 统计；失败锁定按账号统计，两者不是同一计数器。
- 时长持久化统一使用秒，前端按对应字段显示秒或分钟。次数、时长必须为正整数，并在实现契约时明确合理上下限，同步前后端校验；关闭开关不清空参数。
- 第一版页面时长统一显示秒：请求统计时长 1～3600 秒，请求次数 1～10000 次；失败统计时长、锁定时长 60～86400 秒，失败阈值 1～100 次。前端、API、RPC 校验保持一致。
- 参数范围属于可调整的业务策略，不在数据库设置范围 CHECK。通过增量迁移 `20260930142445_remove_login_security_range_checks.sql` 移除原有五项范围约束，保留字段类型、NOT NULL、默认值、主键和 `id = 1` 约束；不改写已执行的建表迁移。直接 SQL 写入仍须遵守业务规则，运行时加载配置继续执行校验。

### 请求限流

- 在 System API 增加轻量中间件，第一版仅挂载 `POST /auth/login`。通过 `.api` 契约声明并重新生成路由，不修改生成的 Handler 或路由文件。
- 中间件只负责读取配置、识别客户端 IP、调用限流组件、放行或返回错误；不处理验证码正确性、密码校验或账号失败锁定。
- 使用当前 go-zero 的 `core/limit.PeriodLimit`，复用现有 go-zero Redis 客户端和原子 Lua 计数，不自行实现另一套固定窗口算法。
- 按“客户端 IP＋稳定接口标识”独立计数，多实例通过 Redis 共享额度。Key 的生成集中维护，不直接使用含查询参数或任意动态路径值的原始 URL。
- 第一次请求启动固定窗口；后续请求只增加计数，不延长窗口。前 N 次放行，第 N+1 次起拒绝；到期后重新开始，不是严格滑动窗口，也不是令牌桶。
- 所有到达该中间件的请求都计数，不区分后续登录成功、失败或参数错误。限流发生在参数解析、查库和 bcrypt 校验之前。
- 超限返回 HTTP 429 和统一错误响应，文案为“请求过于频繁，请稍后再试”；不进入登录业务，不逐条写数据库登录日志。
- 之后真正实现获取验证码接口时，复用同一中间件和配置，但按接口分别计数。例如 60 秒 30 次表示登录、验证码各有 30 次额度，不是两者共用 30 次。本次不创建验证码路由。
- 不限制刷新 Token、其他业务接口，不撤销已有会话。
- 代理信任规则采用“默认信任全部，配置后只信任指定范围”：`Auth.TrustedProxies` 未配置或为空列表时，优先采用 `X-Forwarded-For`，没有时采用 `X-Real-IP`；都没有则使用连接来源 IP。配置了 CIDR 列表后，仅采信指定来源的转发头，其他来源使用连接 IP。可信代理属于部署配置，不扩展为本次管理页面功能。

### 失败锁定

- 由 System RPC 的登录 Logic 编排，在凭证校验前检查锁定，在校验失败或成功后更新保护状态；不把这部分业务逻辑塞入请求限流中间件。
- 按现有用户名规范化规则生成账号计数标识，不按 IP 区分，同一账号从不同 IP 发起的失败会共同累计。
- 从第一次凭证失败开始建立固定统计窗口，后续失败不延长统计窗口。失败统计时长和锁定时长是两个独立参数。
- 用户不存在、密码错误累计失败次数；参数错误、账号停用、数据库或 Redis 等基础设施错误不作为密码失败累计。
- 达到阈值时锁定指定时长。锁定期间不再校验密码、不继续累计失败、不延长锁定时间；到期后重新开始失败统计。
- 登录成功清除对应失败计数。若该请求通过锁定检查后，其他并发失败请求刚刚建立锁定，不删除这个新锁定；已开始且凭证正确的请求可以完成。开启失败锁定不使已有 Session 或 Refresh Token 失效。
- 计数、达到阈值后的锁定及相关状态调整使用 Redis Lua 原子执行，避免并发请求丢失计数或覆盖锁定状态；不通过 PostgreSQL 锁、提高隔离级别或分布式锁实现。
- 达到阈值的那次凭证失败仍按现有规则记录登录日志；后续因已锁定而直接拒绝的请求不逐条写数据库登录日志。
- 超管与普通账号使用相同规则。没有可用会话时，超管被锁定也需要等待到期；第一版不新增解锁入口或隐含豁免。

### 数据模型与接口

- 新增 `sys_security_config`，全系统一条记录，`id` 为 `BIGINT` 主键且约束为 `1`，由数据库迁移插入初始配置。
- 使用明确的类型化字段，不采用用户可任意增删的字符串 key/value 配置平台，不放入字典表。

| 字段 | PostgreSQL 类型 | 含义 |
| --- | --- | --- |
| `id` | `BIGINT` | 固定为 1 |
| `login_rate_limit_enabled` | `BOOLEAN` | 请求限流开关 |
| `login_rate_limit_window_seconds` | `INTEGER` | 请求统计时长 |
| `login_rate_limit_max_requests` | `INTEGER` | 窗口内最大请求次数 |
| `login_failure_lock_enabled` | `BOOLEAN` | 失败锁定开关 |
| `login_failure_window_seconds` | `INTEGER` | 失败统计时长 |
| `login_failure_threshold` | `INTEGER` | 失败次数阈值 |
| `login_lock_duration_seconds` | `INTEGER` | 锁定时长 |
| `created_at` | `TIMESTAMPTZ` | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 最后修改时间 |

- 本表不提供新增、删除操作，无软删除字段，不为单行配置增加额外索引。不向用户表增加失败计数或锁定字段。
- 管理接口为 `POST /security/login/get`、`POST /security/login/update`，遵守现有 API → RPC 分层和统一响应规范，并登记菜单与 API 权限。
- 更新请求必须包含登录保护整组字段，不设计成可选字段 PATCH。显式传入 `false` 必须能关闭开关，不能因 ORM 忽略零值而漏更新。
- Repository 使用明确字段集合的一条 `UPDATE`，不对整个持久化模型调用 `Save`。无需为单条更新额外包事务，也不使用显式行锁。
- 未来实际增加其他安全分类时，再增加相应字段及分类级查询、更新接口；只提交、更新当前分类，不跨分类整包覆盖。
- 同一分类并发保存采用后保存覆盖先保存，不额外引入版本冲突交互；不同分类的保存不得覆盖彼此字段。

### 配置加载、多实例与异常

- 配置表由 System RPC 访问，API 不新增普通业务数据库连接。一个 Model 对应一个 Repository，沿用现有 Logic 分层，不新增 Service 层。
- API、RPC 使用进程内配置快照，登录热路径不为读取配置逐次查询数据库；API 所需配置通过内部 RPC 获取，不借用受终端用户权限控制的管理 HTTP 请求加载。
- 配置保存成功后刷新当前实例的快照，通过 Redis 发布变更通知；其他实例收到通知重新读取配置，不把本地热更新误称为所有实例即时生效。
- 使用低频重载兜底遗漏通知，属于内部配置同步，不建设业务定时任务平台。具体周期和生效延迟在实现时明确并验证。
- 实现使用 Redis Pub/Sub 变更通知和每 30 秒一次的重载。依赖健康时漏通知通常在下一次重载后生效，仍需加上查询耗时；网络或数据库故障时不承诺 30 秒内同步成功。先订阅再加载，RPC 进程仍在启动时从数据库加载配置，失败不启动；API 进程启动只建立订阅，不要求配置 RPC 调用成功。
- API 采用旁路加载：登录请求有有效内存快照时直接使用，没有时通过 RPC 加载、校验并缓存。后台通知和周期重载也可提前填充缓存。加载失败返回 HTTP 503，不按默认关闭保护放行；失败后按实例退避 1 秒，再允许请求触发重试。
- API 使用 `golang.org/x/sync/singleflight` 合并同一实例并发的缺缓存加载；等待者可随自己的请求取消而退出，共享加载独立于任一请求取消，受进程关闭和 5 秒上限约束（实际 RPC 客户端超时仍适用）。加载后再次读取时返回独立快照。显式通知和周期重载不被 singleflight 吞掉、不受请求退避限制，并与旁路加载串行，避免旧查询结果覆盖已处理的新配置。
- 运行期间重载失败仍使快照不可用，受保护登录返回 503，后续旁路加载或后台重载成功恢复。API 不新增普通业务表访问权限；进程存活不代表就绪，现有 `/ready` 继续检查 RPC 及数据库、Redis 等依赖，不以进程能启动为由直接报就绪。
- Redis 通知在数据库写入之后执行，不放入数据库事务。通知失败不能声称数据库修改已回滚，必须记录并明确反馈同步异常，由重载兜底恢复。
- 已开启的保护遇到 Redis 故障时返回服务暂不可用，不静默放行、不自动降级为各进程独立计数，也不把故障伪装为密码错误或超限。
- 未能取得有效配置时，不通过默认关闭保护绕过错误；配置加载失败及已有快照的处理需保持失败关闭原则，不能以零值配置替代已生效配置。
- 修改参数不批量清空已有计数或锁定。已有临时状态保留原 TTL，到期后按新参数建立状态；关闭开关后停止执行对应检查，不主动扫描、删除历史状态。因此短时间关闭后重新开启，尚未到期的状态仍可能生效。
- 临时状态由 Redis TTL 自动过期，不使用 `KEYS`、全库清空或定时清理任务。

### 实现与部署说明

- 部署先执行数据库迁移，API 与 RPC 不再要求固定启动先后。API 的 RPC 客户端保持 `NonBlock: true`；RPC 尚未可用或旧版 RPC 缺少配置接口时，API 可启动但登录配置加载失败，登录返回 503。旁路加载不消除版本兼容要求，滚动升级仍建议先升级 RPC 以减少不可用窗口。数据库、Redis 和 Casbin 的现有启动依赖不变。
- 部署配置 `Auth.TrustedProxies` 默认为空，表示信任所有代理；未配置与显式 `[]` 语义一致。非空配置使用 CIDR，例如 `127.0.0.1/32`、`10.0.0.0/24`、`::1/128`。任意条目格式错误均阻止 API 启动，不退回信任全部。
- 多层代理场景：默认模式取转发链最左侧地址；配置可信范围后，从右往左跳过可信代理，取第一个不可信地址；整条链都可信时取最左侧地址。多行 `X-Forwarded-For` 合并解析，格式异常则回退连接 IP。此解析同时用于登录日志 IP 与限流 IP，保证两者一致。
- 默认模式面向 Nginx／网关统一入口的部署：API 端口必须限制为仅代理可访问，最外层代理覆盖客户端传入的转发头，受控内层代理再按需追加。跨机器或容器部署可通过非空 CIDR 列表收紧信任范围；本次不增加自动探测或额外告警机制。
- 限流键为 `dogx:auth:rate:<接口标识>:<IP>`；失败状态键为 `dogx:auth:failure:<小写用户名的 SHA-256>`，单个 Redis Hash 从计数状态原子转换为锁定状态。使用内置过期机制，不使用分布式锁。
- 同步通知使用 `dogx:security:config:changed`，通知不携带配置内容，接收端重新读取数据库；热路径只读本地快照。Pub/Sub 复用现有 go-redis 依赖，不引入新的包。
- 验证码失败是否累计账号失败次数仍待单独讨论，本次不定义也不实现验证码规则。

## 取舍与限制

- IP 固定窗口允许窗口交界处的短时突发，不承诺任意连续时间段都不超过配置次数；第一版不开放算法选择。
- 同公司出口 IP 会共享对应接口的额度，需要根据实际使用人数调整限额；IP 限流不能单独防止分布式攻击。
- 默认信任全部以部署便利为优先，并不自动验证代理身份。若 API 可被用户直接访问，伪造转发头可能绕过 IP 限流、污染登录日志；采用默认模式必须落实入口代理和网络隔离。按账号失败锁定的计数维度不受此变更影响。
- 按账号锁定可防止换 IP 持续猜测，但攻击者也可能故意制造失败，暂时锁定他人账号。接受此取舍，超管不豁免；已有会话不受影响。
- Redis 故障时拒绝受保护登录，优先保证规则不被绕过，代价是登录可用性依赖 Redis。
- 配置多实例同步是最终一致，不承诺原子切换所有实例；发布通知和低频重载不能替代明确的生效延迟说明。
- 登录日志不包含每次限流、锁定拦截，后续安全预警不能只依赖登录日志表推断全部攻击请求。本次不扩展预警系统或逐请求安全事件存储。

## 验证

- 验证初始化默认值、字段类型和范围、整组保存、`false` 正常更新、无变更仍提交，以及不覆盖其他分类字段。
- 验证普通角色按菜单和 API 授权访问，没有额外超管限制；未授权访问由后端拒绝，超管也参与限流与失败锁定。
- 验证固定窗口第 N/N+1 次边界、到期、重复拒绝不延长 TTL、不同 IP 和接口独立计数、多实例共享计数及可信代理 IP 识别。
- 验证未配置、空列表默认采信转发头；非空列表拒绝未受信来源的转发头；多层代理、IPv6、无转发头和异常格式的回退，以及非法 CIDR 阻止启动。确认默认限流键使用转发的用户 IP，而不是代理 IP。
- 验证未知用户名、错误密码、参数错误、停用账号及基础设施错误的计数区别，阈值锁定、到期重新统计、成功清除、已有会话保持有效。
- 使用真实 Redis 验证并发计数和锁定原子性、Redis 故障处理、修改配置不清空旧状态及关闭再开启的行为。
- 验证限流和锁定拒绝不写数据库登录日志、不执行后续密码校验，触发阈值的凭证失败正常写日志。
- 验证配置通知、漏通知重载、同步失败反馈和多实例生效；保持现有单元测试、集成测试、安全矩阵及覆盖率检查。
- 验证 API 先于 RPC 启动、首次登录旁路加载、并发合并、失败退避与恢复、请求取消不影响其他等待者、运行时关闭取消共享加载，以及通知不会被在途加载吞掉；RPC 的首次数据库配置加载仍失败关闭。
- 测试按现有资源约束串行、低并发运行，Go 构建缓存与临时目录使用 D 盘，不为本功能增加前端生产构建验证。
