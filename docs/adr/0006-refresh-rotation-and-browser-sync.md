# ADR-0006：刷新令牌幂等窗口与浏览器凭据同步

- 状态：已接受
- 日期：2026-09-24
- 补充并部分替代：[ADR-0003](0003-authentication-and-session.md) 的刷新令牌重用规则

## 背景

同源窗口共享持久化凭据，但各自持有 Pinia 内存快照。一个窗口刷新后，另一个窗口可能继续提交旧 Refresh Token，触发重用检测并撤销整个 Session。即使同步内存，两个窗口仍可能同时提交同一个令牌；刷新成功但响应丢失也会导致相同问题。

## 决策

### 服务端

- 保留随机 Refresh Token、7 天滑动 Session、15 分钟 Access Token，以及窗口外重用时撤销整个 Session 的规则。
- 首次成功轮换建立固定 5 秒幂等窗口。窗口内只接受当前或紧邻上一代 Refresh Token，返回首次签发的同一组 Access/Refresh Token；不再轮换、不延长窗口或 Session TTL。更早或不匹配的令牌仍撤销 Session。
- 重复结果保留首次签发时的角色快照；窗口内角色启停不会改变该结果，窗口后的下一次真实轮换重新加载角色。撤销 Session 的操作仍立即阻止后续刷新。
- 使用 Redis 服务端时间在单键 Lua 中完成比较、轮换、窗口设置和结果选择，禁止先在 Go 中依据旧快照撤销会话。并发请求只能有一个结果获胜。
- Session 增加上一代摘要、窗口截止时间和加密刷新结果，不增加 Redis 缓存键、数据库表或分布式锁。结果使用 AES-256-GCM，随机 nonce，以 Session ID 作为附加认证数据；从现有服务端 AccessSecret 用 HMAC-SHA256 和独立用途标签派生加密密钥，不能直接复用 JWT 签名密钥作为 AES 密钥。所有 RPC 实例必须使用相同配置。
- 密文含绝对 Access Token 到期时间，重放返回的 expiresIn 按剩余时间计算，不能让客户端误以为旧 JWT 的有效期被延长。
- 窗口是逻辑有效期，不是字段 TTL；过期密文不得被返回，下次轮换覆盖，Session 删除时一起删除。API SessionReader 不解密、不使用该结果。
- 每次返回结果都必须经过同一 Session 的原子检查；注销后不得从独立缓存复活会话。加密结果损坏、密钥不一致或 Redis 故障返回技术错误，不跳过认证。

### 浏览器

- 沿用 Pinia 和当前 localStorage/SecureLS 适配，不额外引入 useStorage、browser-tabs-lock 或另一套凭据存储。
- 集中监听认证持久化键的 storage 事件，同步凭据；刷新前主动读取共享存储，覆盖休眠窗口遗漏通知的情况。同步不应触发跨窗口回写循环，其他状态写入也不能覆盖较新的凭据。
- 保留单窗口刷新排队。旧请求的 401、刷新失败或迟到的成功响应，不能覆盖其他窗口的新凭据或恢复已退出的登录。
- 网络/服务端技术错误不能直接清空登录；只有仍对应当前凭据的确定认证失败才执行重新认证。
- 新会话/账号切换不能沿用旧账号页面权限快照，窗口应重新加载以重建用户与路由状态。
- 不依赖 Web Locks 或 HTTPS 安全上下文实现同步；HTTP 传输风险不由本方案消除。

## 取舍与部署

- 这是明确的安全例外：持有上一代令牌的人在 5 秒内也可能取得新凭据。它兼顾合法并发和丢失响应，不代表零重放风险；窗口不得被重复请求滑动延长。
- 不取消重用检测；不把基于 localStorage 的模拟锁作为正确性保障；不因一个浏览器特性强制所有局域网部署改为 HTTPS。
- 不修改数据库隔离级别，不扩展本次范围到用户会话 Set 残留及批量注销并发问题。
- 旧 Session 缺少新增字段时允许正常首次轮换。旧版 RPC 不理解幂等窗口，发布须避免新旧 RPC 混跑；回滚可能使已打开窗口重新登录。更换 AccessSecret 同样会使旧 JWT/加密结果不可用。

## 验证

- 并发旧令牌和窗口内新令牌请求获得相同 Token；Session TTL、窗口不被重复请求延长。
- 窗口截止边界、上一代之外的令牌、窗口外重用仍撤销；其他 Session 不受影响。
- 注销/全部注销后的重试失败，不复活 Session；密文不能跨 Session 使用或被篡改。
- 使用真实 Redis 验证 Lua 并发路径；单元测试覆盖加解密、错误路径及到期时间。
- 前端验证存储事件、主动同步、SecureLS、回写循环、未相关字段写入、迟到成功/失败、退出及会话切换。
